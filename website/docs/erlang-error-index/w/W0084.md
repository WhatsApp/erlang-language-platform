# W0084 - attribute_order

**Severity:** Warning (disabled by default)

## Problem

This diagnostic fires when module-level attributes do not follow the canonical
ordering.

```erlang
-module(main).
-compile(warn_missing_spec_all).
-oncall("an_oncall").
%% ^^^^^^^^^^^^^^^^^^^ 💡 warning: W0084: `-oncall` must appear before `-compile`.
```

## Explanation

Some codebases mandate a fixed ordering for module-level attributes so that file
headers stay consistent and easy to scan. This diagnostic enforces the following
order:

1. `-module`
2. `-author`
3. `-oncall`
4. `-moduledoc`
5. `-compile`
6. `-behaviour`
7. `-export`
8. `-export_type`
9. `-include` / `-include_lib`
10. `-type` / `-opaque` / `-nominal`
11. `-define`
12. `-record`

Ordering is checked per file: attributes pulled in from an included header are
not mixed with the including module's attributes.

The diagnostic is disabled by default. Enable it in the lint configuration:

```toml
[linters.attribute_order]
enabled = true
```

## Fix

Reorder the attributes to match the canonical order.
